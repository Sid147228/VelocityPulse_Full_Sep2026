How VelocityPulse Fits Together

Each feature has a distinct purpose so the same result can be understood from several angles without conflicting logic.

1. Run / UploadCreate or import a JMeter test result.
2. ReportUnderstand one test in detail.
3. CompareMeasure change between two tests.
4. TrendSee movement across many tests.
5. BaselineDefine historically acceptable performance.

Feature Definitions

What each major page is for and when to use it.

PROJECTS

Application / Project

A logical workspace that keeps reports, trends, comparisons and baselines separated for one application.

  • Prevents data from different applications being mixed.
  • The active project is shown in the header and can be switched safely.
HOME

Upload Result

Imports a JMeter CSV/JTL result, parses transactions, calculates performance metrics and generates a report.

  • Use when a test already ran outside VelocityPulse.
  • Can apply a saved baseline to the report.
REPORT

Single Test Report

The detailed view of one performance test, including transaction metrics, graphs, observations and overall RAG status.

HISTORY

Report History

The project-scoped list of saved reports. Use it to reopen past results and select reports for comparison or trend analysis.

COMPARE

Report Comparison

Compares two test reports transaction-by-transaction. It highlights metric movement and whether performance improved or degraded.

TREND

Trend Analysis

Shows how performance changes across multiple runs over time. Avg, P90, P95 and Error % can be trended.

  • History Stability describes run-to-run consistency.
  • A saved baseline can be selected as an optional reference.
BASELINE

Performance Baseline

Builds a statistically informed reference from recent historical runs and creates per-transaction P90 Green/Amber thresholds.

  • Saved baseline versions are immutable.
  • Only sufficiently stable transactions are promoted.
RUN TEST

Run JMeter Test

Launches a JMeter test from VelocityPulse using an uploaded JMX and supporting files, then saves the resulting report in the active project.

LIVE

Live Progress

Shows progress and live test activity while a JMeter execution is running. Project switching is blocked during an active test to avoid cross-project contamination.

MONITORING

Real-time Monitoring

Displays live server/performance monitoring data when monitoring is configured for the test environment.

EXPORT

PDF / CSV Export

Creates portable output for sharing test results, comparisons and supporting evidence outside the web UI.

AUTH

User Login

Local user authentication with project ownership. User and performance data remain local to the VelocityPulse installation.

Performance Metric Glossary

The most common terms used throughout reports, comparisons, trends and baselines.

TermDefinitionHow to interpret it
TransactionA named JMeter request, sampler or transaction controller represented in the report.Transactions are matched by exact name across reports, trends and baselines.
# SamplesThe number of requests/samples included for a transaction.Higher sample counts usually provide stronger evidence than very small runs.
Average / AvgThe arithmetic mean response time across samples.Useful for overall performance, but it can hide slower tail responses.
P90 / 90th PercentileThe response time at or below which 90% of samples completed.VelocityPulse uses P90 as the primary baseline threshold signal.
P95 / 95th PercentileThe response time at or below which 95% of samples completed.Shows slower tail behaviour and is included in stability analysis.
Error %The percentage of samples that failed.Higher error percentage indicates functional or performance-related failures during the test.
Throughput / TPSThe rate at which requests or transactions are processed over time.Use with response time to understand whether the system stayed fast while handling load.
RAGRed / Amber / Green status used to summarise performance against thresholds.Green = acceptable, Amber = warning, Red = threshold breach.
BaselineA saved, immutable performance reference created from stable historical runs.Use it to judge whether later tests remain within accepted performance limits.
Green P90 ThresholdThe P90 limit below which the transaction is considered Green.Calculated from historical P90 mean plus observed variation, with minimum headroom.
Amber P90 ThresholdThe higher P90 limit before the transaction becomes Red.Crossing Green enters warning; crossing Amber becomes Red.
History StabilityHow consistent Avg, P90 and P95 have been across the selected test history.Stable ≤10% variation, Variable 10–20%, Unstable >20%.
Baseline StatusThe latest P90 result compared with a selected saved baseline.It answers “Is the latest result acceptable against this baseline?”
Coefficient of Variation (CV)Standard deviation divided by the mean, expressed as a percentage.It measures relative run-to-run variation; lower is more consistent.
CoverageThe percentage of selected reports in which a transaction has valid data.VelocityPulse requires at least 60% coverage for baseline eligibility.
ConfidenceA qualitative indication of how strong the historical evidence is for a baseline candidate.High confidence needs more runs, higher coverage and lower variability than Moderate confidence.
Baseline EligibleA transaction that has enough history, coverage, P90 data and consistency to be promoted into a baseline.Current rule: at least 3 runs, at least 60% coverage, P90 present and variation ≤15%.
ImprovedA later result is faster/lower for the compared response-time metric.Interpret with the selected metric and test conditions.
DegradedA later result is slower/higher for the compared response-time metric.A degradation does not automatically mean a baseline breach.
Not ComparableThere is not enough matching/valid data to make a fair comparison.Often caused by missing transactions or missing metric values.

Baseline & Trend — What Is the Difference?

These features are connected, but they answer different questions.

BASELINE

What is acceptable?

Baseline Analysis learns from recent stable history and creates transaction-specific Green and Amber P90 thresholds.

TREND

Where are we heading?

Trend Analysis plots multiple runs over time and highlights movement, variability and optional baseline status.

COMPARISON

What changed between two tests?

Comparison focuses on exactly two reports and calculates metric deltas transaction-by-transaction.

Important: History Stability and Baseline Status can disagree without being contradictory. A transaction can be Stable + Red (consistently slow) or Unstable + Green (acceptable now, but historically inconsistent).

Status Meanings

The same words can appear in different parts of the tool; these definitions explain the context.

GREEN

Within accepted threshold

For a baseline-applied report, P90 is at or below the baseline Green threshold.

AMBER

Warning zone

P90 is above the Green threshold but at or below the Amber threshold.

RED

Threshold breach

P90 is above the baseline Amber threshold.

STABLE

Consistent history

Maximum CV across Avg, P90 and P95 is at or below 10%.

VARIABLE

Noticeable variation

Maximum CV is greater than 10% and at or below 20%.

UNSTABLE

High variation

Maximum CV is above 20%.

INSUFFICIENT

Not enough evidence

VelocityPulse does not have enough valid data to calculate a reliable stability result.

Local Data, Privacy & Storage

VelocityPulse is designed to run locally without requiring an external performance-data service.

Local SQLite Database

Projects, report history, baselines and run context are persisted in a local SQLite database created automatically on first use.

No Separate Database Server

SQLite is embedded. End users do not need to install or run MySQL, PostgreSQL or another database service.

Automatic Backups

Versioned local backups are created with retention controls so an accidental file issue is less likely to destroy all historical data.

Integrity Checks

The local persistence layer performs database integrity checks and provides guarded restore logic.

Raw Test Evidence

JMeter result files and generated runtime artefacts remain local to the installation and are separate from the SQLite metadata store.

Project Isolation

Reports and baselines are stamped with a project ID so one application's history does not appear in another application's analysis.

Quick Interpretation FAQ

Common questions a new user may have while reviewing results.

Why can a result be Stable but Red?

Stable describes consistency across history. Red describes the latest P90 against the accepted baseline. Consistently slow results can therefore be Stable and Red.

Why does Trend show a gap for one transaction?

The transaction was missing or had no valid value in that test. VelocityPulse keeps the date aligned and shows a gap rather than shifting the next value to the wrong test date.

Why is a transaction not eligible for Baseline?

Typical reasons are too few runs, less than 60% coverage, missing P90 data, or run-to-run variation above the 15% promotion limit.

Does “Degraded” always mean the test failed?

No. Degraded means the selected metric is worse than the earlier comparison report. A degradation can still remain within the accepted baseline.

What should I look at first in a report?

Start with overall RAG, Error %, P90/P95, then check transaction-level outliers and supporting graphs. Use Trend for direction and Baseline for accepted limits.
